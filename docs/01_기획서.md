## 1. 한 줄 소개

**논문을 읽고 싶지만 허들이 있는 개발자를 위해, AI가 질문하고 내가 답하면서 내 말로 요약을 완성하게 돕는 서비스**

- 키워드: **LLM 백엔드**

## 2. 왜 만드나

- 직접 논문을 읽어 보니 두 군데가 무거웠다.
  1. **시작:** 내용보다 "논문을 읽는다"는 이름 자체가 부담이다.
  2. **정리:** 문답은 따라가지만, 마지막에 **내 말로 두세 줄 요약**하는 게 어렵다.
- 기존 서비스(예: 라이너 스칼라)는 **AI가 대신 요약**해 준다. 빨리 파악하기엔 좋지만 내 것으로 남지 않는다.
- 우리는 **AI가 대신 읽어 주는 도구가 아니라, 내가 이해하고 체화하게 돕는 도구**로 차별화한다.

## 3. 대상과 범위

| 항목 | 내용 |
|---|---|
| 대상 | 논문을 읽고 싶은 개발 취준생·주니어 개발자 |
| 읽을거리 | 논문부터 시작 → 기술 블로그로 확장 |
| 분야 | 개발·AI부터 시작 (세무·경제 등 확장은 논의 중) |

## 4. 핵심 흐름

```
논문 업로드
  → 5분 분량 조각으로 나눔 (시작 허들 낮추기)
  → AI가 조각마다 질문
  → 내가 답함
  → 내 답을 모아 요약 초안 제시 ("쓰기"가 아니라 "고치기")
  → 내가 고쳐서 요약 완성
  → 확인 질문 통과 시 "설명할 수 있음"
```

**실제 사례 (Attention Is All You Need)**
- 처음 쓴 문장: "트랜스포머로 번역한 문장들은 비약적으로 (기존 대비 몇 퍼센트?) 상승했으며…"
- 고친 문장: "영어→독일어 번역 점수(BLEU)는 기존 최고 기록보다 2점 이상(약 8%) 올랐고, 영어→프랑스어도 기존의 4분의 1도 안 되는 학습 비용으로 최고 기록을 냈다."
- 확인 질문 3개 통과 → 이 과정을 서비스로 만든다.

## 6-1. 사용 경험에서 나온 아이디어 (11/27)

J가 BERT 논문을 AI와 문답으로 다시 읽으면서 겪은 것을 기능 아이디어로 정리했다. 확정이 아니라 논의할 거리다.

1. **이해 → 내 말로, 두 단계로 나누기**
   - 겪은 것: AI 설명을 따라 치면서 이해는 됐지만, 그건 내 말로 만든 게 아니었다.
   - 아이디어: "AI 질문 → 내가 답함"으로 바로 가지 않고, **① 설명을 따라 치며 이해하는 단계 → ② 안 보고 내 말로 한 줄 쓰는 단계**로 나눈다. 노트에도 "이해(따라 친 것)"와 "내 말로" 칸을 따로 둔다. 시작 허들(2번)이 더 낮아진다.
   - 더 나아가 난이도를 단계로 둘 수 있다: 따라 치기 → 핵심 단어 빈칸 → 둘 중 고르기 → 내 말로.

2. **설명 형식은 "정의 먼저, 비유는 보조"**
   - 겪은 것: 비유만 가득한 설명은 쉬워 보여도 정확한 이해가 남지 않았다. "정의에 기반해서 비유를 채우자"로 바꾸니 잘 읽혔다.
   - 아이디어: AI 설명 형식을 `정의 → (비유 한 줄) → 예시 → 확인 질문`으로 고정한다. → **답변 형식 일관성(지호 딥다운)**의 첫 규칙 후보.

3. **개념 하나 → 떠올려 보기 질문 하나**
   - 겪은 것: BERT를 ① 사전 학습·미세 조정 ② 양방향 ③ MLM ④ NSP로 쪼개고, 개념마다 한 줄 질문에 답하니 부담 없이 끝까지 갔다.
   - 아이디어: "5분 분량 조각"을 글자 수가 아니라 **개념 단위**로 자른다. 조각마다 확인 질문은 하나만.

4. **까먹었을 때 다시 시작하기 (복습)**
   - 겪은 것: 일주일 만에 BERT를 다시 열었더니 ①부터 까먹어서 처음부터 다시 읽었다.
   - 아이디어: 며칠 뒤 그 논문의 "떠올려 보기" 질문만 다시 보내는 **복습 기능**. 틀린 개념의 조각만 다시 열어 준다.
